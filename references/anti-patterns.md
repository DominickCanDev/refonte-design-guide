# Anti-Patterns

Use during audits and when reviewing your own proposal.

## Hierarchy

- Card soup: every value gets its own card, icon, and heading.
- Competing primary actions with equal visual weight.
- Decoration, effects, or motion that outweigh the task itself.
- Essential and supplementary information presented with the same emphasis.
- A repeated value or message presented as if it were new information.
- The same information repeated across components with no additional meaning.

## Simplification

- Hiding a cost, error, condition, or frequent action to make the screen look
  lighter.
- "Modernization" with no identified reading, decision, or journey problem.
- Removing information without saying where it remains available.
- Shrinking text to fit a composition instead of reflowing it.
- Filling empty space with content that serves no task.

## Behavior

- A control that looks wired but has no effect.
- A false success message, or success announced before confirmation.
- Failure rendered as an empty state.
- Retry that can duplicate a submission or an irreversible action.
- A one-off override of a shared component that silently changes other screens.

## Evidence

- Placeholder or invented data presented as real content.
- Visual judgment stated as verified user behavior.
- A screenshot used to claim interaction or state coverage.
- Vague justification such as "cleaner" or "more modern" without a concrete
  consequence.
